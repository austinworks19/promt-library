# Prompt 10: Post-Project Retrospective Summary

# Prompt Text
"Here are raw notes from a project wrap-up discussion: [PASTE NOTES/TEAM COMMENTS]. Summarise into: (1) What went well, (2) What didn't go well or caused delays, (3) One or two concrete process changes to consider for next time. Keep it factual and specific — avoid vague statements like 'communication could be better' unless the notes explain what actually happened. Do not assign blame to individuals; focus on the process."

# Intended Workflow/Task
Turning a team's informal end-of-project discussion or comments into a short retrospective summary that actually gets saved and referenced, instead of lessons living only in people's memory.

# Problem Being Solved
Small teams rarely have time to write up formal retrospectives after a project wraps, so the same avoidable issues (e.g., unclear scope, late client feedback) tend to repeat across multiple projects without anyone noticing the pattern.

# Automation Potential
works well if the team already jots down quick notes or comments after a project, but doesn't remove the need for someone to actually hold a short wrap-up conversation in the first place.

# Risks and Limitations
Can only summarise what's in the notes — if feedback is vague or one-sided, the retrospective will be too; risk of unintentionally singling someone out if the notes themselves mention a person's mistake, so output should be checked before circulating to the wider team; shouldn't replace an actual conversation for sensitive issues (e.g., a team conflict).
