# Prompt 07: Final Deliverable QC Check Before Client Delivery

# Prompt Text
Here's the deliverable spec from the client brief: [PASTE ORIGINAL SPECS, e.g., format, duration, aspect ratio, deadline]. Here's what we're about to send: [PASTE FILE DETAILS, e.g., filename, duration, resolution, format]. Compare the two and tell me: (1) Does everything match? (2) List any mismatches clearly. (3) List anything in the original spec that isn't confirmed either way (e.g., spec mentioned captions but file details don't say if captions were added). Don't assume something is fine just because it wasn't mentioned in the file details — flag it instead.

# Intended Workflow/Task
A final check before sending a deliverable to the client, comparing what was originally requested against what's actually about to go out.

# Problem Being Solved
Deliverables sometimes go out to clients with a mismatched spec (wrong aspect ratio, missing captions, wrong duration) because the final check relies on someone remembering all the original requirements from a brief written weeks earlier.

# Automation Potential
could run as a mandatory step before any file is marked "ready to send" in the project tracker, catching mismatches before they become a client-facing problem.

# Risks and Limitations
Only as reliable as the information typed in — if the file details given are wrong or incomplete, it can't catch a real mismatch; doesn't replace someone actually opening and watching/checking the file; shouldn't be the only quality check for high-stakes client deliverables.
